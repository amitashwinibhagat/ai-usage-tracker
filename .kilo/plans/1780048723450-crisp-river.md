# Provider-Agnostic UI Restructure Plan

## Problem Statement

The app currently supports 9 AI providers (Claude, Codex, Gemini, Copilot, Kimi, DeepSeek, GLM, Qwen, MiniMax) but the UI treats Claude as the primary/special provider everywhere:

1. **App branding** — "Claude Usage Tracker" in all 13 localization files, sidebar header, About page
2. **Sidebar "Credentials" section** — Only Claude connections (Claude.ai, API Console, CLI Account) get first-class treatment as individual items. All other 8 providers are buried under a single "AI Providers" menu item
3. **Menu bar popover** — Built around `ClaudeUsage` as the primary display type; multi-AI dashboard is a secondary card at the bottom
4. **Settings navigation** — `.claudeCode` has its own sidebar entry; no equivalent for other providers
5. **Code semantics** — Feature flag `.multiAI` frames non-Claude providers as an add-on; `MenuBarManager` centers on Claude

## Scope of Changes Required

### 1. App Rebranding
- **All 13 localization files** (`app.name` key): "Claude Usage Tracker" → new provider-agnostic name
- **Sidebar brand header** (`SettingsView.swift:358-365`): "Claude Usage / Tracker" → new name
- **About page** (`AboutView.swift`): Update direct-distribution messaging
- **Feature flag description** (`FeatureFlags.swift:68-69`): "Multi-AI tracking (Claude + Codex + Gemini + Copilot)" → neutral description

### 2. Sidebar Restructuring (`SettingsView.swift`)
Current structure:
```
ESSENTIALS
  Claude.ai
  API Console
  CLI Account
SETTINGS
  Appearance
  General
  History
APP
  Pro Features
  AI Providers        ← 8 providers buried here
  Manage Profiles
  ...
```

Proposed structure (provider-agnostic):
```
[Active Profile switcher]

PROVIDERS
  [All connected providers shown equally]
  Claude.ai
  API Console
  Codex
  Gemini
  Copilot
  ...
  [+ Add Provider button]

SETTINGS
  Appearance
  General
  History

APP
  Pro Features
  Manage Profiles
  Language
  Shortcuts
  Updates
  Support
  About
```

On **Free tier**, only Claude providers show. On **Pro tier**, all configured providers show equally.

### 3. Consolidate Provider Credential Views
- Merge `PersonalUsageView`, `APIBillingView`, `CLIAccountView` into the unified provider architecture
- Each provider gets a consistent credential sheet pattern (already partially done in `AIProvidersSettingsView`)
- Remove the hardcoded "Claude.ai / API Console / CLI Account" credential cards from `ProfileCredentialCardsRow`

### 4. Popover Restructuring (`PopoverContentView.swift`)
- Make the primary dashboard provider-agnostic: show usage from the **active** provider(s), not hardcoded Claude
- On Free: Claude remains the only visible provider (business model constraint)
- On Pro: Show a provider-selector or unified aggregate view at the top, not as a secondary card
- Multi-AI dashboard (`MultiAIDashboard`) should be the primary view on Pro, not a bottom card

### 5. MenuBarManager Decoupling (`MenuBarManager.swift`)
- `MenuBarManager` is currently hardcoded to `ClaudeUsage` as its primary `@Published` usage type
- Needs to support a provider-agnostic `currentUsage` that can be any `ProviderUsage`
- Or maintain a `currentProvider: AIProvider` alongside the usage data

### 6. Profile Model Considerations (`Profile.swift`)
- Claude fields (`claudeSessionKey`, `apiSessionKey`, `cliCredentialsJSON`) are at the top level
- Other providers are namespaced (`codexApiKey`, `geminiApiKey`, etc.)
- **Decision needed**: Keep current model (migration cost) or normalize all provider credentials into a dictionary/map structure

### 7. Localization Impact
- 13 language files need `app.name` updates
- New sidebar section labels: "section.providers", "section.add_provider"
- Claude-specific credential labels may need neutralizing

## Decisions (User Confirmed)

| Question | Decision |
|----------|----------|
| **Q1: App name** | **"AI Usage Tracker"** — fully rebrand across all 13 localization files, sidebar header, and About page |
| **Q2: Free tier UI** | **Show all providers with Pro locks** — Free users see all 9 providers in the sidebar; non-Claude ones render as disabled/upsell rows (teaser UI) |
| **Q3: Sidebar display** | **Individual sidebar rows** — Each provider is its own row in the sidebar under a unified "Providers" section |
| **Q4: Menu bar icon** | **Aggregate across all providers** — Icon shows combined usage (e.g., total active providers, aggregate tokens, or overall percentage) |
| **Q5: Data model** | **Keep current model** — Claude fields stay top-level, others stay namespaced. No migration. Fastest path. |

## Implementation Phases

### Phase 1: Rebranding (Low Risk)
- Update `app.name` in all 13 localization files
- Update `SidebarBrandHeader` text
- Update About page copy
- Update `FeatureFlags.swift` comments/descriptions

### Phase 2: Sidebar Restructure (Medium Risk)
- Replace `ProfileCredentialCardsRow` with dynamic provider list
- Update `SettingsSection` enum to use provider-agnostic cases
- Add `isFreeTier` filter logic to sidebar provider list
- Update all localization strings for new section labels

### Phase 3: Popover Provider-Agnostic Dashboard (High Risk)
- Refactor `MenuBarManager` to support generic `ProviderUsage` instead of hardcoded `ClaudeUsage`
- Redesign `PopoverContentView` top section to be provider-selectable
- Make `MultiAIDashboard` the primary Pro view

### Phase 4: Credential View Consolidation (Medium Risk)
- Merge Claude credential sheets into unified provider pattern
- Remove hardcoded Claude credential views from sidebar direct navigation
- Ensure all providers use consistent `ProviderCard` + sheet pattern

## Risks
- **Localization drift**: 13 language files must stay in sync
- **MenuBarManager refactor**: Core app logic; regression risk in menu bar icon rendering
- **User confusion**: Existing users accustomed to Claude-first UI may need onboarding
- **Free tier gating**: Must ensure non-Claude providers remain properly paywalled after restructure
