# Product Strategy: Claude Usage Tracker — Revenue-Focused Roadmap

**Stakeholder Decisions (Locked):**
- **Goal:** Revenue
- **Platform:** macOS only (terminal statusline integration is our moat)
- **Scope:** Claude first, then Codex, Gemini, Copilot (sequentially)
- **Monetization:** $4.99/mo Pro tier + $9.99/user/mo Team tier
- **Distribution:** Direct (DMG + Paddle), NOT App Store
- **License:** Fully closed-source
- **Free Model:** Feature-limited free forever (not time-limited trial)

---

## Current State

Claude Usage Tracker is the most feature-rich native macOS menu bar app for tracking Claude AI usage (2.5k+ GitHub stars). Recently added Limit Optimization tips (21-tip catalog) and Session Planning.

**Primary persona:** macOS-based AI power users (developers, agencies, freelancers) who juggle multiple AI tools and accounts.

## Feature Roadmap (Revenue-Optimized)

### Phase 1: Pro Tier Foundation (Weeks 1–3)
**Goal:** Build the feature gating infrastructure and ship the first Pro-exclusive features that drive conversions.

#### 1.1 License / Subscription Infrastructure
**What:** In-app purchase via App Store or Paddle (for direct distribution). Feature gate system that checks license validity.
**Why:** Without this, nothing else matters. Must be rock-solid before any Pro features ship.
**How:**
- Add `LicenseManager` service with receipt validation
- Add `FeatureFlags` system with `.free`, `.pro`, `.team` tiers
- Add "Upgrade to Pro" upsell surfaces throughout the UI
- Graceful degradation: Pro features show as locked with preview text

**UI Changes:**
- Settings sidebar: "Pro Features" section with locked indicators
- Popover: Upsell banner when approaching free limits
- Profile creation: "Upgrade to Pro to add more profiles" prompt at 2 profiles

#### 1.2 Burn Rate Predictor (Pro)
**What:** "At your current pace, you'll hit 100% in X minutes" with trend arrow.
**Why:** #1 user-requested feature. Directly solves surprise usage. Strong Pro conversion driver.
**How:** Linear extrapolation from usage history tokens-per-minute.

#### 1.3 Cost Transparency (Pro)
**What:** Show API-equivalent cost for subscribers. "$12.40 today at API rates vs your $20/mo Pro subscription."
**Why:** Pro/Max subscribers have zero visibility into value. This creates FOMO for the free tier.
**How:** Static pricing table × usage data.

#### 1.4 Smart Notifications (Pro)
**What:** Contextual alerts with actionable advice.
**Why:** Makes notifications genuinely useful rather than just noisy.
**How:** Extend existing NotificationManager with contextual message generators.

#### 1.5 Profile Limit (Free Gate)
**What:** Hard cap at 2 profiles for free users.
**Why:** The core persona (multi-account operators) hits this immediately. Natural conversion point.
**How:** Block profile creation at index 2, show upgrade prompt.

### Phase 2: Claude Deepening & Pro Differentiation (Weeks 4–8)
**Goal:** Make the Claude tracking experience best-in-class before expanding to other providers.

#### 2.1 Per-Session Conversation Breakdown (Pro)
**What:** Drill down into which conversations burned the most tokens.
**Why:** Attribution = optimization. Users want to know what's expensive.
**How:** Parse per-conversation data from Claude.ai API. Store and display.

#### 2.2 Cross-Profile Unified Dashboard (Pro)
**What:** Single view showing all profiles' usage side-by-side with aggregate totals.
**Why:** Multi-account operators currently switch profiles or look at multiple menu bar icons.
**How:** Aggregate data from all profiles. New view or popover mode.

#### 2.3 Context Window Tracker (Pro)
**What:** Show how much of the 200K context window is used in Claude Code sessions.
**Why:** Context window anxiety is real. Users lose work when context gets compacted.
**How:** Read from `/context` command output or statusline data.

#### 2.4 Predictive Throttling Alerts (Pro)
**What:** "You typically burn 80% of your weekly limit by Thursday. Pace yourself today."
**Why:** Goes beyond reactive tracking to proactive planning. Justifies recurring subscription.
**How:** Statistical model using historical usage patterns (day-of-week, time-of-day).

#### 2.5 Usage History Export (Pro)
**What:** Export usage data to JSON/CSV for billing reconciliation.
**Why:** Freelancers need this for client invoicing.
**How:** File export with date range picker.

### Phase 3: Multi-AI Expansion (Weeks 9–14)
**Goal:** Add Codex, Gemini, and Copilot to capture multi-AI users. Only after Claude experience is best-in-class.

#### 3.1 OpenAI Codex Integration (Pro)
**What:** Track Codex CLI usage via OpenAI API.
**Why:** #2 most requested feature. Claude Code users often also use Codex.
**How:** New credential type, API client, usage model. Provider badges on rows.

#### 3.2 Gemini CLI Integration (Pro)
**What:** Track Google Gemini CLI usage.
**Why:** Aggressive pricing makes Gemini popular for cost-conscious developers.
**How:** API key auth, usage fetching. Reuse Codex infrastructure.

#### 3.3 GitHub Copilot Integration (Pro)
**What:** Track Copilot usage (suggestions accepted, code generated).
**Why:** Many developers have Copilot as baseline. Shows full spending picture.
**How:** Copilot usage API via GitHub OAuth.

#### 3.4 Unified Multi-AI Dashboard (Pro)
**What:** Single view showing all providers with aggregate cost.
**Why:** "I spent $47 this week across Claude, Codex, and Copilot" is powerful.
**How:** Aggregate all provider usage models into unified view.

### Phase 4: Team Tier & Retention (Weeks 15–20)
**Goal:** Launch Team tier and add features that reduce churn.

#### 4.1 Team Dashboard (Team)
**What:** In-app dashboard showing all team members' usage.
**Why:** Agencies need visibility into collective burn.
**How:** Local network sync or encrypted file sharing.

#### 4.2 Budget Alerts & Webhooks (Team)
**What:** Slack/Discord notifications when team hits budget thresholds.
**Why:** Operations teams need automated alerts.
**How:** Webhook dispatcher with configurable endpoints.

#### 4.3 Weekly Digest (Pro)
**What:** Automated summary: "Last week: X tokens, Y providers, $Z saved vs API pricing."
**Why:** Reminds users of value, reduces silent churn.

#### 4.4 Advanced Icon Styles (Pro)
**What:** Premium visual styles for menu bar (animated, gradient, custom shapes).
**Why:** Small but delightful differentiator.

### Phase 5: Retention & Growth (Ongoing)
**Goal:** Reduce churn and increase ARPU.

#### 5.1 Weekly Digest Email (Pro)
**What:** Automated email every Monday: "Last week you used X tokens across Y providers. You saved $Z vs API pricing."
**Why:** Reminds users of value, reduces silent churn.

#### 5.2 Referral Program
**What:** "Give a month free, get a month free."
**Why:** Organic growth from existing user base.

#### 5.3 Annual Plan Discount

## Technical Architecture for Monetization

### Feature Gating System
```
enum LicenseTier: String {
    case free
    case pro
    case team
}

protocol FeatureGate {
    var requiredTier: LicenseTier { get }
    func isAvailable(for tier: LicenseTier) -> Bool
}

// Usage
class FeatureFlags {
    static let burnRatePredictor = ProFeature()
    static let unlimitedProfiles = ProFeature()
    static let multiAI = ProFeature()
    static let teamDashboard = TeamFeature()
    // ...
}
```

### License Validation
- **App Store:** Use `StoreKit` for IAP receipt validation
- **Direct (Paddle):** Validate license key against Paddle API
- **Offline grace period:** 7 days of cached validation before features lock
- **No phone-home on every launch:** Validate periodically (daily), not per-feature-check

### Privacy-First Design
- **No usage data sent to our servers** — all tracking is local
- **License validation only** sends minimal metadata (version, install ID)
- **Team tier sync** can use local network or encrypted file sharing (no central server)

## Pricing Psychology & Conversion Strategy

### Conversion Funnel
1. **Download (Free)** — GitHub releases + word of mouth
2. **Activate** — Setup wizard gets them tracking within 60 seconds
3. **Engage** — Daily menu bar usage creates habit
4. **Hit Limit** — 2-profile cap creates natural friction point
5. **Upgrade** — Contextual upsell at moment of need

### Upsell Surfaces
| Surface | Trigger | Message |
|---------|---------|---------|
| Profile creation | Attempting to create 3rd profile | "Pro users track unlimited profiles. Upgrade for $4.99/mo." |
| Popover | Usage > 80% | "Pro shows time-to-limit prediction. Upgrade to never be surprised again." |
| Settings | Clicking Pro feature | "This feature requires Pro. See what you're missing →" |
| Notification | Hitting 90% | "Pro users get contextual tips at 75%, 90%, 95%. Upgrade for smarter alerts." |
| Weekly summary | Always (Pro preview) | "This week you used X tokens. Pro would show you cost breakdown." |

### Free Tier Design Philosophy
The free tier must be:
- **Useful enough** to create daily habit (basic tracking, 2 profiles)
- **Limited enough** that power users hit friction quickly (no prediction, no multi-AI, no export)
- **Transparent** about what's locked (never hide Pro features, always show preview)

## Risk Mitigation

| Risk | Mitigation |
|------|-----------|
| Users hate paywalling existing features | All current features remain free. Only NEW features are Pro. |
| License cracking | Paddle server-side validation + offline grace period. No App Store = no easy piracy vectors. |
| Feature bloat | Strict ICE scoring. Kill features with < 5% usage. |
| macOS-only limits growth | Accept this. Better to own one platform than be mediocre on three. |
| Anthropic API changes | Abstract provider interfaces. Isolate API-specific logic. |
| Open-source backlash | Communicate clearly: "Core tracking stays free. Pro pays for ongoing development." |
| Direct distribution friction | Manual DMG downloads vs App Store convenience. Counter with better onboarding + GitHub community. |
