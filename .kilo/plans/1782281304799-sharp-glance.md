# Popover UX Redesign v2 — Sharp Glance

> **Status:** Plan — ready for review  
> **Last updated:** 2026-06-24  
> **Decision summary:** Replace the single-metric hero ring with a dual-metric session/weekly hero, collapse dead space, surface multi-AI and multi-profile status inline, and reorganize details so the popover answers "which limit is the constraint?" in one glance.

---

## Strongest Objection First

The current 5-card popover is not broken — it is **incomplete**. Users open it to answer one question ("Do I have room to keep working?"), but the layout only shows *one* of the two Claude limits at a time and buries every other signal (other providers, other profiles, API cost, context window) behind a segmented toggle or an expander. A bigger ring and more cards is not the fix. The fix is a denser, hierarchy-driven layout that shows the limiting factor first.

---

## Problem Statement

**Who has this problem:** Daily Claude users on macOS who keep AI Usage Tracker in the menu bar and check the popover several times a day. Many run multiple profiles (work/personal) and have connected Codex, Gemini, or Copilot credentials.

**How painful it is:** Medium-high. The popover is the app's most frequently opened surface, yet it forces users to interact (toggle session/weekly, expand Details) to understand their true constraint. In the screenshot you shared, the ring shows **16%** while the secondary line reveals **Weekly: 41% · 410,000 tokens** — the more important number is visually deprioritized.

**How we know:** The current code defaults the ring to whichever percentage is higher, but once the user toggles it, the default is lost. The Details disclosure hides API cost, context window, multi-AI status, and conversation breakdown by default. Multi-profile users only see other profiles in a separate ResetCountdownCard or not at all in the main flow.

**What happens if nothing is built:** Users continue to misread their constraint, scroll the popover to find hidden info, and under-utilize the multi-AI/multi-profile features we already built. The app feels like a usage *reader* instead of a usage *advisor*.

## Target User & Job-to-be-Done

**Primary user:** A knowledge worker with 2–4 Claude profiles and at least one other AI provider connected.

**JTBD:** *"Before I start another Claude conversation, I want to know which account or limit is the constraint so I don't get cut off mid-task."*

**Secondary JTBD:** *"If Claude is tight, which other provider still has room?"*

---

## Goals

1. **Show both session and weekly usage simultaneously** at the top of the popover so the limiting limit is obvious without interaction.
2. **Reduce vertical height and dead space** so the entire useful state fits in one glance (target: ≤520 px tall, no scroll for 80% of users).
3. **Surface connected AI providers** in the popover when credentials exist — currently hidden behind Details.
4. **Surface multi-profile status** as a compact, scannable accordion instead of fragmented cards.
5. **Preserve the dark, premium, Apple-like aesthetic** and existing design tokens.

## Non-Goals

1. **Do not redesign the menu bar icon.** The icon and its rendering pipeline stay as-is.
2. **Do not add new data sources or providers.** We surface what already exists.
3. **Do not change Settings structure or onboarding.** This plan is scoped to the popover surface only.
4. **Do not add new notifications, alerts, or thresholds.** Use existing `NotificationManager` behavior.
5. **Do not add analytics/telemetry.** The app has none; keep it that way.

## User Stories (INVEST)

### Story 1 — Dual-metric hero
> As a Claude user with both session and weekly limits, I want to see both percentages at once so I don't have to toggle to find the constraint.

**Acceptance criteria:**
- Popover shows Session and Weekly rings side-by-side in the hero card.
- Each ring displays percentage, label, and `used / limit tokens`.
- A single status badge above the rings calls out the current constraint (e.g., "Weekly is the limiting factor").
- The higher percentage ring uses the more urgent color.

### Story 2 — Smart summary bar
> As a user near a limit, I want reset time and pace forecast combined in one scannable line so I can decide whether to keep working.

**Acceptance criteria:**
- Reset time and pace forecast live in a single compact card below the hero.
- If pace is unreliable, the line hides the forecast and shows "More usage needed for pace forecast".
- If reset is < 24 h away, the time remaining is highlighted in warning color.

### Story 3 — Multi-AI provider strip
> As a user with multiple AI providers connected, I want to see which providers still have room without expanding Details.

**Acceptance criteria:**
- A horizontal strip of chips appears only when `profile.hasMultiAICredentials` is true.
- Each chip shows provider icon and a status word: "OK", "Watch", or "Critical" (or actual percentage where available).
- Tapping a chip opens Settings → AI Providers for that provider.
- Providers with no usable data show "Connected" instead of a fake percentage.

### Story 4 — Multi-profile accordion
> As a multi-profile user, I want to see my other profiles' session/weekly status in a compact list so I know if I should switch.

**Acceptance criteria:**
- When `profiles.count > 1`, a collapsible "Profiles at a glance" section appears.
- Each row shows profile name, session %, weekly %, and time-to-reset.
- Tapping a row switches the popover to that profile's data (same as clicking its menu bar icon).
- The current active profile is marked with an "Active" badge.

### Story 5 — Empty / no-credentials state
> As a new user with no credentials, I want the popover to guide me to connect instead of showing blank rings.

**Acceptance criteria:**
- If `!profile.hasUsageCredentials`, the hero shows a friendly empty state: "Connect Claude.ai to start tracking" + "Set up" button.
- The button opens the setup flow / Settings → Personal Usage.
- No fake 0% rings are rendered.

### Dimensions

- **Width:** 360 px (down from 400 px) — enough for two 72 px rings + padding.
- **Max height:** 520 px when multi-profile accordion is expanded.
- **Default height:** ~380 px for single-profile, single-provider users.

### Component Specs

#### 1. DualMetricHero
- Two circular progress rings, 72 px diameter, 8 pt stroke.
- Left ring = `effectiveSessionPercentage`; right ring = `weeklyPercentage`.
- Color logic reused from `UsageRingCard`: success / caution / warning / error.
- Status badge above rings reads:
  - `effectiveSessionPercentage >= weeklyPercentage`: "Session is the limiting factor"
  - `weeklyPercentage > effectiveSessionPercentage`: "Weekly is the limiting factor"
  - Both < 50%: "Plenty of room"
  - Session expired / no session data: "Session not active"
- Token label uses existing formatted helpers.

#### 2. SmartSummaryBar
- Combines `ResetCountdownCard` and `BurnRateCard` into one horizontal card.
- Left column: reset icon + "Resets in 4h 35m".
- Right column: trend icon + pace sentence.
- If no reliable pace, right column shows "Not enough usage yet to forecast pace" in muted text.

#### 3. ProviderAvailabilityStrip
- Horizontal `ScrollView(.horizontal, showsIndicators: false)`.
- Chips reuse `AIProvider.brandColor` and `AIProvider.icon`.
- Each chip background is brand color at 0.08 opacity, stroke at 0.18.
- Status word derived from provider usage percentage where available; otherwise "Connected".
- Hidden entirely if `!profile.hasMultiAICredentials`.

#### 4. CrossProfileAccordion
- Reuses logic from existing `CrossProfileDashboard` but renders as a collapsible section inside the popover.
- Default state: **collapsed** unless the active profile is at ≥ 80% usage (then auto-expand to prompt a switch).
- Each row is tappable to set `MenuBarManager.clickedProfileId` and refresh displayed usage.

#### 5. Details Disclosure (reorganized)
Keep the existing disclosure but flatten the content:
- API cost row (if `apiUsage != nil`)
- Context window row (if `sessionTokensUsed > 0`)
- Cost transparency row (if calculable)
- Conversation breakdown (if available)
- Remove the generic "Multi-AI row" — it is replaced by ProviderAvailabilityStrip.

#### 6. Footer
- Primary: `Details ▾` toggle.
- Secondary: `History` button opens Settings → History.
- Secondary: `Settings` button opens Settings.

## Key Flows

### Flow A — Daily check (single profile, Claude only)
1. User clicks menu bar icon.
2. Popover opens to dual-metric hero + smart summary.
3. User sees limiting factor immediately.
4. No scroll, no toggle.

### Flow B — Provider shopping (multi-AI user)
1. User clicks menu bar icon.
2. Hero shows Claude session/weekly.
3. Provider strip shows Codex/Gemini/Copilot status.
4. User taps Gemini chip → Settings opens to AI Providers > Gemini.

### Flow C — Profile switching (multi-profile user)
1. User clicks menu bar icon.
2. "Profiles at a glance" is expanded because active profile is at 85%.
3. User taps another profile row.
4. Popover updates to that profile's data; menu bar active indicator updates.

### Flow D — First launch / no credentials
1. User opens popover.
2. Hero shows empty state with "Connect Claude.ai" CTA.
3. User taps CTA → Settings or setup wizard opens.

## Open Questions

1. **Single-ring fallback?** Should we keep the old single-ring layout as a user preference?  
   *Recommendation:* No. Ship one improved layout; add a preference only if feedback demands it.

2. **Provider strip data granularity?** Should chips show actual percentages for providers that support them (Codex/Gemini/DeepSeek balance) or only OK/Watch/Critical?  
   *Recommendation:* Show percentage where `ProviderUsage` exposes a meaningful percentage; otherwise show "Connected".

3. **Chinese providers?** Kimi/DeepSeek/GLM/Qwen/MiniMax are currently hidden from Settings UI per the free pivot. Should the strip still surface them if credentials exist from older installs?  
   *Recommendation:* Yes, surface any provider with stored credentials; hide only the Settings UI for adding new ones until real APIs land.

4. **Context window and API cost priority?** These currently live in Details. Should any be promoted above the fold?  
   *Recommendation:* Keep them in Details. The hero + summary + providers is already denser; promoting more would harm scannability.

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Two rings feel cramped at 360 px width | Medium | Medium | Prototype at 320 px and 400 px; choose width after 3 internal reviews. |
| Users prefer the aesthetic of the single large ring | Medium | Low | Run preference test with 5 users before shipping. If 3+ prefer old layout, reconsider default. |
| Provider strip shows stale data (providers refresh at different intervals) | Medium | Medium | Add subtle "Updated %@m ago" footnote under strip; use existing `lastUpdated` timestamps. |
| Multi-profile accordion auto-expansion feels noisy | Low | Medium | Only auto-expand at ≥ 80%; respect user's last manual toggle state. |
| Accessibility regression with dual rings | Low | High | Add `accessibilityLabel` to each ring and the status badge; run VoiceOver check. |
| Increased CPU from two rings + sparkline | Low | Medium | Keep rings as `Canvas`/`Shape`, not animation-heavy; profile render time. |

## Single Riskiest Assumption

**Assumption:** Users want both session and weekly visible simultaneously rather than a focused single-metric view.

**Cheapest test before code:** Build a static Figma/SwiftUI preview of the dual-metric hero and show it to 5 existing users (or team members who use the app). Ask: "At a glance, which limit is the constraint?" If ≥ 4 answer correctly in < 3 seconds, proceed. If not, iterate on the ring size, labeling, or badge wording before writing production code.
